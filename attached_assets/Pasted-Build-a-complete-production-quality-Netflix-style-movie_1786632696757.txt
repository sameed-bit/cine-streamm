Build a complete, production-quality Netflix-style movie and TV streaming platform.

The project should be a real working full-stack application, not just a visual mockup.

## TECH STACK

Use:

* React
* TypeScript
* Vite
* Tailwind CSS
* shadcn/ui
* React Router
* Supabase for authentication and database
* TMDB API for movie, TV, actor, poster and backdrop metadata
* Responsive iframe-based video player integration
* Clean reusable component architecture

Use environment variables for all API keys and secrets.

Never expose private server-side secrets in frontend code.

Integrate TMDB API properly.

Create a dedicated service layer:

src/services/tmdb.ts

Do not scatter API calls throughout components.

* Trending movies
* Popular movies

* Top rated TV
* Now playing
* Upcoming
* Movie details
* TV details
* Credits
* Similar movies
* Similar TV shows
* Search movies
* Search TV
* Search people
* Genres
* Movie images
* TV images

getPopularTV()

getMovieCredits(id)
getTVCredits(id)

# 8. RESPONSIVE VIDEO PLAYER

Create:

src/components/VideoPlayer.tsx

The player should be responsive and maintain a 16:9 aspect ratio.

For authorized movie content, dynamically construct:

https://www.vidking.net/embed/movie/{TMDB_ID}?autoPlay=true

For authorized TV content:

https://www.vidking.net/embed/tv/{TMDB_ID}/{SEASON}/{EPISODE}?autoPlay=true&nextEpisode=true&episodeSelector=true

Do not hardcode movie IDs.

Generate the URL dynamically from route parameters.

Player page should contain:

* Responsive iframe
* Fullscreen support
* Loading state
* Error state
* Back button
* Movie/show title
* Episode title where applicable
* Previous/next episode controls where appropriate
* Recommended content below player

Do not download, scrape, proxy, or store video files from the external player.

# 9. WATCH PROGRESS

Implement watch-progress tracking.

Listen for postMessage events from the embedded player.

Support:

* play
* pause
* timeupdate
* seeked
* ended

Store:

* TMDB ID
* media type
* current playback position
* duration
* percentage watched
* season
* episode
* last watched timestamp

Logged-in users should have their progress stored in Supabase.

For guests, temporarily store progress in localStorage.

When reopening content, show:

"Continue Watching"

and resume from the stored position where supported.

# 20. SECURITY

Implement Supabase Row Level Security.

Users should only be able to:

* Read/update their own profile
* Read/write their own favorites
* Read/write their own watch history

Only admins should be able to manage:

* Users
* Featured content
* Homepage configuration
* Administrative settings

Do not trust frontend role checks alone.

Enforce authorization through database policies/server-side logic.

Never expose:

* Supabase service-role keys
* TMDB private credentials
* Admin secrets
